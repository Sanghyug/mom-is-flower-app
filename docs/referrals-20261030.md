## 초대 흐름

1. 충전하기 → 친구 초대 링크 만들기 → 친구에게 보내기 또는 링크 복사.
2. 공개 `/invite/:code` 페이지에서 친구가 토스 또는 웹 환경을 선택.
3. 처음 지갑을 연결할 때 서버가 초대 코드를 조회해 초대한 계정을 귀속. 이후 기존 계정에는 소급 등록하거나 초대자를 바꿀 수 없음.
4. AI 분석에 성공해 유료 조회 정산을 완료하는 Firestore 트랜잭션 안에서 첫 성공을 기록하고 초대한 계정에 +5. 분석 실패·식물 미발견·중복 요청에는 초대 보상 없음.
5. 한국 시간 하루 최대 3명. 한도를 넘긴 친구의 첫 성공은 다음 날 이월 지급하지 않음. 받은 초대 보상·잔액 새로고침 또는 지갑을 열어 확인. 지갑이 열려 있으면 30초 간격으로 갱신.

새 친구는 Firebase 계정과 지갑 첫 연결 기준. 같은 계정 자기 초대는 차단하지만 익명 인증만으로 실제 사람·기기의 동일성을 완전히 구별하지는 못함. 기존 IP별 신규 지갑 생성 한도와 초대한 계정의 하루 보상 한도를 유지함.

## 구현

- 신규 서버 전용 컬렉션: plant_referral_links, plant_referral_codes, plant_referral_members.
- 공개 코드에 UID나 연락처는 포함되지 않음. 공개 초대 페이지도 계정 식별자를 반환하지 않음.
- 첫 연결 시 초대 정보를 저장하고 기존 지갑은 수정하지 않음. 클라이언트가 성공을 주장하는 보상 청구 API는 없음. 종료된 contactsViral 호출은 제거했고 기존 sendViral 보상 티켓 경로도 차단.
- 새 웹/PWA는 초대 페이지를 앱 화면 캐시로 대체하지 않도록 제외. 기존 PWA 캐시가 있는 브라우저는 새 서비스워커 적용 후 한 번 새로고침해야 초대 페이지가 보일 수 있음.
- 토스는 Environment.initialURL 및 웹 쿼리에서 코드를 읽음. 테스트 스킴으로 진입했다면 생성하는 초대 링크에 해당 테스트 deploymentId를 유지해 친구도 같은 테스트 버전을 열 수 있게 함. 이 네이티브 두 기기 전달은 휴대폰 추가 확인 필요.
- 초대 코드는 첫 진입 값을 기기에 최대 7일 보관. 최초 지갑 귀속 후에는 서버의 기록을 사용.
