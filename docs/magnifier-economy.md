# 돋보기와 리워드 운영

## 이번에 반영한 정책

| 항목 | 돋보기 |
| --- | --- |
| 익명 계정 최초 연결 | +10, 계정당 한 번 |
| 식물 이름·꽃말·유래·신화·설화 함께 찾기 | -1 |
| 메모 작성·카드 저장·저장된 이야기 읽기 | 추가 소모 없음 |
| 토스 공유 완료 `sendViral` | +2 |
| 보상형 광고 `userEarnedReward` | +5 |
| 새 꽃말 유래·설화 생성 | 기본 찾기에 포함, 추가 소모·별도 AI 호출 없음 |

공유 후 주소 복사, 공유창 취소, 광고창 닫기, 단순 광고 노출에는 보상을 지급하지 않습니다.
카드의 일반 이미지 공유와 돋보기 보상을 받는 토스 연락처 공유는 별도 동작입니다.
운영 첫값은 하루 공유 1회·광고 5회입니다. `src/lib/creditPolicy.ts`에서 변경합니다.

확정한 과금은 이름 찾기 1개뿐입니다. 추가 기능은 예를 들어 ‘유래·설화 묶음 2개’를 검토할 수 있으나 **코드에 가격으로 반영하지 않았습니다.** 이미 저장된 이야기는 그대로 읽습니다.

## 서버 원장

- 기존 Firebase 프로젝트의 익명 인증 ID 토큰을 서버 Admin SDK로 검증합니다.
- 최초 10개 지급, 차감, 환급, 보상을 Firestore 트랜잭션으로 처리합니다.
- 요청 ID와 사진 해시를 확인합니다. 같은 완료 요청은 결과를 돌려주며 중복 차감하지 않습니다.
- 이름을 식별하지 못했거나 모델/서버 오류가 난 요청은 환급합니다.
- 서버가 비정상 종료해 남은 차감 예약은 2분 뒤 잔액 조회 시 복구합니다. 실제 모델 요청은 25초에 제한됩니다.
- 광고·공유에는 서버가 발급한 티켓을 사용하고 같은 티켓은 한 번만 지급합니다. 티켓은 15분간 유효합니다.
- 지급 확인 전 연결이 끊기면 영수증을 기기에 남기고 다음 조회 시 다시 확인합니다.
- 서버 원장이 없거나 인증에 실패하면 AI 호출을 허용하지 않습니다.

초기 비용 상한은 사용자당 하루 분석 시도 50회, 서비스 전체 하루 200회(`AI_DAILY_LIMIT`)입니다. 실패·환급도 시도 수에 포함합니다. 익명 계정 재발급을 통한 무제한 최초 지급을 줄이기 위해 같은 프록시 IP에서 새 지갑 생성은 하루 20개로 제한합니다. 날짜는 한국 시간 기준입니다.

SDK의 완료 이벤트는 **클라이언트 보고**이며, 서버에서 검증하는 광고사 서명 영수증과 같지 않습니다. 티켓 재사용·잔액 위조·초과 지급은 트랜잭션과 한도로 막지만 변조된 클라이언트의 가짜 완료 신고까지 암호학적으로 증명하지는 못합니다. 실제 운영에서 서명 기반 SSV가 제공되면 추가 연결해야 합니다. 익명 계정은 재설치 시 바뀔 수 있으므로, 사람당 평생 최초 1회 지급을 보장하려면 영구 계정 연동이 필요합니다.

## 배포 전에 필요한 설정

1. 기존 Firebase 프로젝트에서 익명 인증과 Firestore를 확인합니다.
2. Vercel 서버 환경변수 `FIREBASE_SERVICE_ACCOUNT_JSON`에 해당 프로젝트 서비스 계정을 설정합니다. 비밀값은 채팅이나 저장소에 넣지 않습니다.
3. `CREDIT_IP_SALT`에 서버 전용 임의 비밀값을 설정합니다. `OPENAI_API_KEY`도 서버 전용으로 유지합니다.
4. `plant_credit_wallets`, 하위 `operations`, `plant_credit_rewards`, `plant_credit_budget`, `plant_credit_signup_limits`는 클라이언트에서 직접 쓰거나 읽지 못하도록 Firestore 규칙을 설정합니다. 서버 Admin SDK만 접근합니다. 기존 광범위한 허용 규칙이 있으면 개별 deny와 OR로 합쳐져 여전히 허용될 수 있으므로 함께 점검해야 합니다. 기존 카드 컬렉션 규칙은 별도로 유지합니다.
5. 운영 정책에 맞는 보상형 광고 그룹과 토스 공유 모듈을 연결합니다. 서버 변수는 `TOSS_REWARDED_AD_GROUP_ID`, `TOSS_SHARE_MODULE_ID`입니다. 해당 값이 없으면 충전 버튼은 실제 모드에서 활성화되지 않습니다.
6. 새 API와 `/api/wallet`을 먼저 미리보기 배포하고 서버 인증·원장·결제 없는 돋보기 흐름을 실제로 검증합니다. 그 후 웹 및 토스 번들을 배포합니다. 구버전의 공개 AI API가 그대로 서비스되면 새 원장이 그 구버전 호출을 제한하지 못합니다.

기기에 저장한 식물카드는 계속 IndexedDB를 사용합니다. 이번 Firebase 재연결은 인증과 돋보기 원장용이며, 사진·메모를 Firebase에 자동 업로드하지 않습니다. 서버는 요청 중 사진을 분석하고 원장에는 사진 해시와 식별 결과만 보관합니다.

## 체험 모드

`VITE_WALLET_DEMO=true`는 Vite **개발 모드에서만** 작동합니다. 이 모드에서는 실제 AI·광고·공유 요청을 하지 않고, 화면에 모의 동작임을 표시합니다. 10개 지급·1개 차감·+2/+5 지급·취소를 비용 없이 확인할 수 있습니다. 운영 빌드에서는 이 플래그가 true여도 모의 잔액으로 AI에 접근할 수 없습니다.

현재 미리보기는 이 체험 모드입니다. Admin 서비스 계정과 실제 SDK 기기 검증을 하지 않은 상태에서 실제 보상·차감이 운영 중이라고 표현하면 안 됩니다.
